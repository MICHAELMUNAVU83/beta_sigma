# BetaSigma — ERP System

## Project overview

Build a full-stack internal ERP for BetaSigma, a software development and AI automations
company operating as the tech arm of GS1 Kenya. The system manages projects, tasks, people,
and notes — with role-based access controlling what each user can see and do.

Built with Elixir and Phoenix LiveView for real-time interactivity, fault tolerance, and
long-lived stateful connections without writing JavaScript.

## Roles

Two roles with distinct access levels, enforced via plug-based authorization:

- **admin** — full access to all modules and user management
- **staff** — access to assigned projects, own tasks, and shared notes

## Router structure

```elixir
defmodule BetaSigmaWeb.Router do
  use BetaSigmaWeb, :router

  pipeline :browser do
    plug :accepts, ["html"]
    plug :fetch_session
    plug :fetch_live_flash
    plug :put_root_layout, html: {BetaSigmaWeb.Layouts, :root}
    plug :protect_from_forgery
    plug :put_secure_browser_headers
    plug :fetch_current_user
  end

  # Public routes — no auth required
  scope "/", BetaSigmaWeb do
    pipe_through :browser
    get "/", PageController, :home
  end

  # Auth routes (generated by mix phx.gen.auth)
  scope "/", BetaSigmaWeb do
    pipe_through [:browser, :redirect_if_user_is_authenticated]
    live "/login", UserLoginLive, :new
  end

  # Internal app — all authenticated roles
  scope "/app", BetaSigmaWeb do
    pipe_through [:browser, :require_authenticated_user]

    live "/projects", ProjectsLive.Index, :index
    live "/projects/new", ProjectsLive.Index, :new
    live "/projects/:id", ProjectsLive.Show, :show
    live "/projects/:id/tasks/:task_id", ProjectsLive.Show, :task
    live "/notes", NotesLive.Index, :index
    live "/notes/:id", NotesLive.Show, :show
    live "/notifications", NotificationsLive.Index, :index
  end
end
```

## Real-time with PubSub

Phoenix PubSub powers live updates across the app without page reloads.
Subscribe in `mount/3`, broadcast inside context functions after writes.

```elixir
# In context — broadcast after a task status change
def move_task(task, new_status) do
  task
  |> Task.changeset(%{status: new_status})
  |> Repo.update()
  |> case do
    {:ok, updated} ->
      Phoenix.PubSub.broadcast(
        BetaSigma.PubSub,
        "project:#{task.project_id}",
        {:task_updated, updated}
      )
      {:ok, updated}
    error -> error
  end
end

# In LiveView — subscribe and handle incoming events
def mount(%{"id" => project_id}, _session, socket) do
  if connected?(socket) do
    Phoenix.PubSub.subscribe(BetaSigma.PubSub, "project:#{project_id}")
  end
  {:ok, assign(socket, project_id: project_id, tasks: list_tasks(project_id))}
end

def handle_info({:task_updated, task}, socket) do
  updated_tasks = update_task_in_list(socket.assigns.tasks, task)
  {:noreply, assign(socket, tasks: updated_tasks)}
end
```

PubSub topics to use:

| Topic                | Events                                   |
| -------------------- | ---------------------------------------- |
| `"project:{id}"`     | task_updated, task_created, task_deleted |
| `"user:{id}"`        | notification_created                     |

## Key LiveView patterns

**Kanban board** — use `phx-hook` with SortableJS via `assets/js/hooks/sortable.js`.
On drop, push a `"move_task"` event to the LiveView which calls `Projects.move_task/2`.
PubSub then updates all other connected users instantly.

**File uploads** — use Phoenix LiveView's built-in `allow_upload/3` for file
attachments. In dev, store to `priv/static/uploads/`. In prod, stream to S3
via `ex_aws_s3`.

**Search and filter** — use `phx-change` on filter inputs with `phx-debounce="300"`,
handle in `handle_event/3`, re-query the context and `assign` fresh results.

**Modals** — use `JS.show` / `JS.hide` with a `<.modal>` core component. Drive
visibility via `:action` in the live route (`:new`, `:edit`) and pattern match in
`handle_params/3`.

**Pagination** — pass `page` as a URL param, handle with `handle_params/3`,
use `Ecto.Query` limit/offset in the context query.

## Getting started

### 1. Create the project

```bash
mix phx.new beta_sigma --database postgres
cd beta_sigma
```

### 2. Add dependencies to mix.exs

```elixir
defp deps do
  [
    {:phoenix, "~> 1.7"},
    {:phoenix_ecto, "~> 4.4"},
    {:ecto_sql, "~> 3.10"},
    {:postgrex, ">= 0.0.0"},
    {:phoenix_html, "~> 4.0"},
    {:phoenix_live_reload, "~> 1.2", only: :dev},
    {:phoenix_live_view, "~> 1.0"},
    {:phoenix_live_dashboard, "~> 0.8"},
    {:swoosh, "~> 1.5"},
    {:finch, "~> 0.13"},
    {:gettext, "~> 0.20"},
    {:jason, "~> 1.2"},
    {:bandit, "~> 1.2"},
    {:oban, "~> 2.17"},
    {:ex_aws, "~> 2.5"},
    {:ex_aws_s3, "~> 2.5"},
    {:bcrypt_elixir, "~> 3.0"},
    {:floki, ">= 0.30.0", only: :test},
  ]
end
```

### 3. Generate auth

```bash
mix phx.gen.auth Accounts User users
mix deps.get
mix ecto.migrate
```

### 4. Generate contexts

```bash
mix phx.gen.context Projects Project projects \
  name:string description:text status:string \
  start_date:date deadline:date budget:decimal

mix phx.gen.context Projects Task tasks \
  title:string description:text status:string priority:string \
  due_date:date estimated_hours:decimal project_id:references:projects

mix ecto.migrate
```

### 5. Start the server

```bash
mix phx.server
# Visit http://localhost:4000
```
